# Goluk Control

Небольшое Android-приложение для локальной работы с видеорегистратором Goluk / GoLook T-series по Wi‑Fi.

## Что умеет MVP

- проверять соединение с регистратором по адресу `http://192.168.62.1`
- показывать системную информацию устройства
- показывать статус SD-карты
- форматировать SD-карту
- получать список роликов по типам `1`, `2`, `4`, `5`
- открывать ролики для воспроизведения
- отправлять GET-команды в API для экспериментального изменения настроек
- выполнять готовые безопасные команды вроде `reboot`

## Архитектура

- Kotlin
- Jetpack Compose + Material 3
- Navigation Compose
- Media3 ExoPlayer для воспроизведения видео
- MVVM
- Репозиторий поверх `HttpURLConnection` без лишних сетевых зависимостей

## Важное ограничение

API у Goluk частично недокументирован. Поэтому экран **«Настройки / API»** сделан честно и безопасно:

- есть список известных endpoint'ов
- можно отправить произвольную query-строку
- приложение показывает сырой ответ API
- предположительные параметры не зашиты жёстко в код без подтверждения

Это значит, что приложение уже годится как рабочий клиент и как база для дальнейшего развития, но для некоторых конкретных параметров настроек понадобится проверить, какие query-параметры принимает именно ваша прошивка.

## Откуда взята база по API

- `videolist`, `video`, `systeminfo`, `sd`, `sdformat`
- строки SDK с endpoint'ами `conf_hdr`, `conf_voice`, `conf_logo`, `reboot`, `time`, `pushstream_*` и др.
- RTSP/preview-механика присутствует отдельно и может быть добавлена следующим этапом

## Как собрать локально

1. Откройте проект в Android Studio.
2. Установите Android SDK Platform 36 и Build Tools 36.0.0.
3. При первом открытии Studio подтянет зависимости.
4. Соберите `debug` или `release` APK.

## Почему в архиве нет готового `gradle-wrapper.jar`

В текущей среде нет установленного Android SDK и нет сетевого доступа для подтягивания Gradle Wrapper / Maven-зависимостей, поэтому проект подготовлен как полноценные исходники для дальнейшей сборки в Android Studio.


## Сборка без Android Studio

В проект уже добавлены два варианта облачной сборки:

- `codemagic.yaml` — для сборки в Codemagic
- `.github/workflows/android-debug.yml` — для сборки в GitHub Actions

### Вариант 1. Codemagic

1. Создайте пустой репозиторий на GitHub.
2. Загрузите в него содержимое этого архива.
3. Подключите репозиторий в Codemagic.
4. Codemagic автоматически увидит `codemagic.yaml`.
5. Запустите workflow `goluk-debug`.
6. Готовый `debug.apk` появится в artifacts.

### Вариант 2. GitHub Actions

1. Создайте репозиторий на GitHub.
2. Загрузите туда содержимое архива.
3. Откройте вкладку Actions.
4. Выберите workflow `Android Debug APK`.
5. Нажмите `Run workflow`.
6. После завершения сборки скачайте artifact `goluk-control-debug-apk`.

### Что делает облачная сборка

- ставит JDK 17
- ставит Android SDK Platform 36 и Build Tools 36.0.0
- скачивает Gradle 9.3.1
- собирает `debug` APK

### Почему я всё ещё не приложил APK прямо здесь

В этой текущей среде я могу подготовить проект и файлы для облачной сборки, но не могу честно собрать installable APK локально, потому что здесь нет исходящего сетевого доступа для Gradle/Maven и Android SDK. Поэтому я добавил готовые конфиги для сборки в браузере без Android Studio.
